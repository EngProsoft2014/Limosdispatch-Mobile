1. اختبار ملكية المصروفات

أُنشئ سجل MOBILE QA إداري غير مرتبط بالسائق وسجل خاص بالسائق، بقيمة 0.01 لكل منهما. استُخدمت هوية السائق العادي لطلبات GET/PUT/DELETE. نجحت 5 تحققات: إخفاء السجل الإداري في القائمة، إبقاء سجل السائق، رفض تعديل الإداري، رفض حذفه، ونجاح تعديل سجل السائق نفسه.

اختُبرت الصلاحيات على السيرفر مباشرة، وليس بمجرد إخفاء أزرار الموبايل. لا تعني هذه الحالات المحددة مراجعة شاملة لكل مسارات التصدير أو كل أشكال إنشاء/تغيير مالك المصروف أو عزل شركتين.

2. دليل الفرق بين الإشعار المحلي وإشعار الخلفية

التجربة الأولى أظهرت إشعارًا محليًا بوسم tag=null، وقناة ride_updates_v2، وصوت android.resource://com.limosdispatch.mobile/raw/limosdispatch_alert. هذا يثبت إعداد الموبايل، ولا يثبت إعداد رسالة FCM التلقائية في الخلفية.

أُعيدت التجربة بصورة مستقلة والتطبيق على شاشة Home دون فتحه حتى قراءة metadata. الإشعار الجديد كان بوسم FCM-Notification، وهو مسار العرض التلقائي للخلفية.

{
  "header": "NotificationRecord(0x0dacac3a: pkg=com.limosdispatch.mobile user=UserHandle{0} id=0 tag=FCM-Notification:74918957 importance=4 key=0|com.limosdispatch.mobile|0|FCM-Notification:74918957|10167: Notification(channel=ride_updates shortcut=null contentView=null vibrate=null sound=null defaults=0x0 flags=0x10 color=0x00000000 vis=PRIVATE))",
  "when": "1794305335213",
  "mCreationTimeMs": "1794305334918",
  "mSound": "content://settings/system/notification_sound",
  "notificationAgeSeconds": 12,
  "channelId": "ride_updates",
  "channelSound": "content://settings/system/notification_sound"
}

الفارق بين when وmCreationTimeMs في هذه الرسالة أقل من ثانية، وعمر الإشعار وقت أخذ العينة نحو 12 ثانية؛ هذه أرقام من تشخيص الجهاز، وليست ادعاء بقياس كامل لزمن التسليم من لحظة الإسناد. لم أجر اختبار استماع مسجل للصوت؛ الدليل هنا هو القناة الفعلية ومورد الصوت الذي اختاره Android.

معرّف رحلة تجربة الخلفية الثانية: 4a7d68d7-4aa8-4d69-ab47-a9a396dc6d18. معرّف الأولى: 4f207094-2c44-4c3a-b8c8-fb8c011a21e2.

3. المطلوب المتبقي من المطور للنغمة

راجع مسار الإرسال المنشور لاختيار قناة Android بحسب appVersion المسجل لكل installation. التطبيق المثبت 1.1 والقناة الجديدة موجودة، لكن إشعار الخلفية اختار القناة القديمة. لم أراجع AppVersion داخل قاعدة البيانات في هذه الجولة؛ يجب تأكيد تحديث التسجيل في السيرفر ثم مقارنة إعدادات رسالة FCM الفعلية.

{
  "android": {
    "notification": {
      "channel_id": "ride_updates_v2",
      "sound": "limosdispatch_alert"
    }
  }
}

الصوت في Android 8 فما بعد تحدده القناة الموجودة على الجهاز؛ إرسال sound وحده لا يغير صوت ride_updates القديمة. حافظ على بيانات فتح الرحلة وnotificationId وcompany وtripId دون استبدالها. إعداد iOS المقترح سابقًا يبقى aps.sound=limosdispatch_alert.wav، لكنه لم يُختبر هنا.

استعلام قراءة اختياري للمطور - بلا Tokens

SELECT n.Id AS NotificationId, n.TripId, d.Platform, d.AppVersion,
       pd.Status, pd.AttemptCount,
       CASE WHEN d.UpdatedAtUtc <= n.CreatedAtUtc THEN 1 ELSE 0 END AS RegistrationBeforeNotification
FROM [Limosdispatch_Master].dbo.PushDevices AS d
JOIN [Limosdispatch_lux].dbo.PushDeliveries AS pd
  ON pd.InstallationId = d.InstallationId AND pd.TenantId = d.TenantId
JOIN [Limosdispatch_lux].dbo.PushNotifications AS n ON n.Id = pd.NotificationId
WHERE n.TripId = '4a7d68d7-4aa8-4d69-ab47-a9a396dc6d18';

هذا الاستعلام مُعد للمراجعة ولم يُنفذ على SSMS في هذه الجولة. راجع أيضًا payload الإرسال بعد حجب token وأي مفاتيح، وأرسل القناة المختارة وappVersion وحالة التسليم فقط.

التنظيف وحدود الاختبار

حُذف سجلا المصروفات التجريبيان. أُلغيت وحُذفت رحلتا إشعار MOBILE QA اللتان أُنشئتا لهذه الجولة فقط، وعُلّمت إشعاراتهما وحدها كمقروءة. لم تُبدأ رحلة أو تُفرض رسوم، ولم تُعدل أو تُحذف بيانات رحلات أو مصروفات حقيقية. تُركت رحلة التتبع الاصطناعية الأقدم بحالتها.

الاختبار الحالي لإشعار إسناد السائق على Android؛ لم تُعَد تجربة حجز الويب أو Extra للأدمن أو صوت iOS. لا نعمم نتيجة التوقيت أو النغمة على أحداث ومنصات لم تُختبر.
